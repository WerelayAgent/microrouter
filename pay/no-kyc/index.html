No KYC, structurally

There is no account to KYC.

The claim is structural: pay to an address, receive a key, and the key is the identity. No account exists for a verification process to attach to.

What we never ask for

  • Asked forName
    AnswerNothing to attach it to
  • Asked forEmail
    AnswerOptional, for balance alerts only
  • Asked forPhone
    AnswerNever
  • Asked forID document
    AnswerNever — there is no verification flow to feed it into
  • Asked forCard
    AnswerOnly if you choose the card rail; crypto rails never see one

Prompts and completions are not stored by default — the storage code does not run. What we keep (token counts, model ids, cost) is listed in the privacy policy.

What “no KYC” does not mean

No KYC means no identity verification. It does not mean every rail is unscreened.

Need no third party in the payment path at all? The self-hosted rail — Monero, shielded Zcash, Lightning, LTC-MWEB, DASH — is waiting on the BTCPay connection.

What accountlessness costs

Save the API key and permanent dashboard link. The link can replace a lost or rotated key without collecting an identity. If both bearer secrets are lost, there is no personal recovery path.

No withdrawals. Credits buy inference and never convert back to coin — a withdrawal path would make us a money transmitter, and money transmitters must KYC. Credits never expire; refunds are service credit.
